## 角色设定

你是一名资深 Flutter 全栈工程师，5 年以上跨平台开发经验，精通 Flutter、Dart、Riverpod、Hive、Dio、go_router、just_audio、audio_service、flutter_tts。

## 项目背景

开发一个"精简版微信读书"App：只保留**阅读器 + 书架 + 听书**，去掉社交和书城。目标是本地优先（无后端）、离线可用的个人阅读/听书工具，视觉和交互对标微信读书的简洁沉浸风格。支持导入的电子书格式：**TXT、EPUB、PDF**。

技术底座：Flutter 3.22+ / Riverpod（若你认为 Bloc 更合适，先说明理由再切换）/ Hive+SharedPreferences 本地存储 / go_router。

## 关键约束（请先确认后再动手）

1. **EPUB 渲染**：Flutter 生态没有成熟的所见即所得 EPUB 渲染库。请明确说明你打算怎么做——是解析 XHTML 后用自定义 Widget 渲染（工作量大但效果好），还是用 WebView 承载 EPUB 内容（工作量小但翻页动画/划线交互受限）。两种方案的取舍点是本项目最大的技术风险，**必须先给出方案对比和你的推荐**，而不是直接假设一种方案能"完美实现"仿真翻页。
2. **PDF 支持**：PDF 是固定排版格式，和 TXT/EPUB 的"重排文本"渲染逻辑完全不同，不能套用同一套翻页/字号调节/划线架构。请明确说明：
   - 用哪个库渲染（如 `pdfx` / `syncfusion_flutter_pdfviewer` / `pdf_render`），并说明选型理由（渲染质量、是否开源免费、是否支持文本选择）
   - PDF 模式下"字体大小/行距调节"这类重排功能大概率不可用，只能提供整体缩放，需要在阅读器 UI 里明确降级，而不是假装支持
   - PDF 的划线/笔记如何定位（一般是页码+坐标，而非 EPUB/TXT 的字符偏移量），Note/Highlight 数据模型需要能同时兼容两种定位方式
   - PDF 转 TTS 朗读：需要先提取纯文本再送入 flutter_tts，提取质量（分栏、页眉页脚、图片说明文字）会直接影响听书体验，请说明文本提取策略和已知局限
   - PDF 目录（书签）解析方式，以及没有目录信息时的兜底方案（按页码分段）
3. **TTS 逐句高亮**：flutter_tts 的字符/单词回调在不同平台（Android/iOS）实现不一致，逐句高亮属于"尽力而为"功能，不是标准能力。请在实现前说明你的检测方案和已知局限，不要承诺 100% 精准同步。
4. **仿真翻页 3D 效果**：属于高难度自定义动画，若时间/篇幅有限，请优先保证"滑动"和"覆盖"两种翻页模式可用，仿真翻页可放在最后、可先给架构占位。
5. **后台音频**：audio_service 需要原生工程配置（Android Service、iOS Background Modes + 音频会话类型），这部分必须给出**可直接抄的原生配置文件内容**，而不是"请自行配置"。

## 输出方式（重要）

- **分批输出，不要一次性塞完**。每次回复只完成一个模块，结尾用一句话确认"是否继续下一步"，等我说"继续"再往下。
- 每个模块输出前先给 3-5 行的模块设计要点（数据流向、关键类职责），再给代码。
- 代码必须是完整可编译的 Dart 文件（含 import），禁止用"// 其余逻辑类似省略"这类占位，除非该部分确实是低优先级的次要页面（如"关于"页可以给骨架）。
- 每个文件顶部注明文件路径（如 `// lib/presentation/reader/reader_page.dart`）。

## 输出顺序

1. 技术选型说明（Riverpod vs Bloc、EPUB 渲染方案、风险点）+ 项目目录结构
2. pubspec.yaml（带版本号，标注每个包的用途一行注释，含 PDF 渲染库）
3. 核心数据模型：Book / Chapter / Note / Highlight / AudioProgress / ReaderSettings（含 Hive TypeAdapter；Book 需要区分格式类型 txt/epub/pdf，Note/Highlight 的定位字段需兼容"字符偏移量"和"页码+坐标"两种方式）
4. 主题配置：浅色 / 深色 / 护眼三套 ThemeData + 全局切换逻辑
5. main.dart + go_router 路由表
6. 书架页面（网格/列表切换、导入本地书籍、长按多选、空状态）
7. 阅读器页面（先给 TXT/EPUB 的"滑动翻页 + 目录 + 底部设置菜单 + 划线笔记 + 进度保存 + 听书入口"MVP 版本；PDF 走独立的页面渲染分支——给出 PDF 阅读器和 TXT/EPUB 阅读器如何共享同一套书架/进度/听书入口，但各自独立渲染实现；仿真翻页作为附加项最后给）
8. 听书沉浸式播放器（含 audio_service 后台播放配置、锁屏控制、语速/定时关闭、听读进度双向同步）
9. 搜索页 + 个人中心/设置页（可适度精简为关键实现）
10. Android/iOS 原生配置清单（后台音频权限、Info.plist、AndroidManifest 具体内容）+ 运行调试说明

- 不做书城/在线书源/版权内容

## 这份提示词相对原版做了什么优化

1. **拆分执行节奏**：原版要求"一次性"产出 10 大项完整代码，对任何模型来说都会导致后面模块被压缩成伪代码或截断。改为分批交付+确认，保证每一步都是完整代码。
2. **提前暴露技术风险**：EPUB 渲染方案、TTS 逐句高亮精度、仿真翻页动画这三点是最容易被模型"假装能完美实现"的地方，加了强制说明要求，避免拿到一堆无法真正跑起来的承诺型代码。
3. **原生配置具体化**：把"后台播放权限配置"从一句话要求变成"必须给出可抄的 Info.plist/AndroidManifest 内容"，避免最后一步变成空话。
4. **降低优先级冲突**：阅读器和听书模块工作量最大，明确"先 MVP 再加分项"的顺序，避免翻页动画细节挤占核心数据流/状态管理代码的篇幅。
5. **保留原版所有功能范围**，只是重排了信息密度和交付节奏，功能没有被砍。
6. **新增 PDF 格式支持**：PDF 是固定排版格式，若直接套用 EPUB/TXT 的重排文本架构（翻页动画、字号调节、字符级划线定位）会导致代码看似支持、实际跑不通。已在约束和输出顺序里明确要求：PDF 走独立渲染分支、明确降级哪些重排功能、划线定位方式与 EPUB/TXT 区分、以及 PDF→TTS 的文本提取策略。
