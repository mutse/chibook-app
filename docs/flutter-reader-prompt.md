## 角色与任务

你是一名资深 Flutter 工程师。请在现有“耳读”项目中继续完善本地阅读与听书功能，并以 `docs/erdu-mockup.html` 为视觉和交互基准。

这是一个已经可以运行的项目。开始工作前必须先阅读现有代码、`README.md`、原型和测试，确认真实实现状态；不要重新初始化 Flutter 工程，不要替换现有状态管理、路由或数据模型，也不要把已实现功能重写成另一套架构。

## 产品定位

耳读是一款本地优先、离线可用的个人阅读与听书 App，只包含：

- 本地书架
- TXT、EPUB、PDF 阅读
- 系统 TTS 听书
- 搜索、阅读设置、笔记与划线
- 本地阅读和听书进度

明确排除书城、在线书源、社交、账号、付费内容和云同步。

### 目标设备

一套 Flutter 代码同时交付以下形态，不做分支工程、不做「平板专用包」：

| 形态 | 典型宽度 | 要求 |
| --- | --- | --- |
| Android 手机、iPhone 竖屏 | < 600dp | 当前基准形态，交互保持不变 |
| 手机横屏、小尺寸 iPad 竖屏、Android 平板竖屏、iPad Split View 1/2 | 600–839dp | 侧边导航栏，内容限宽 |
| iPad 横屏、大尺寸 iPad 竖屏、Android 平板横屏、展开态折叠屏 | ≥ 840dp | 原生平板观感：常驻侧栏 + 双栏对开 |
| iPad Slide Over、Split View 1/3 | 320–450dp | 必须退化回手机形态且不崩溃、不丢播放 |

iOS 已开启 `TARGETED_DEVICE_FAMILY = "1,2"`，且 `Info.plist` 未设置 `UIRequiresFullScreen`，因此 iPad 分屏与随航已经隐式启用——App 会在运行时被系统任意改变尺寸，这不是可选项，必须处理。Android `AndroidManifest.xml` 的 `configChanges` 已包含 `screenSize|screenLayout|density`，Activity 在旋转和分屏时不重建，同样由 Flutter 侧自行响应尺寸变化。

macOS、Web、Windows、Linux 不在范围内，仓库中也没有对应平台目录，不要为它们添加适配代码。

## 微信读书 / 微信听书借鉴边界

参考微信读书与微信听书公开版本中的常驻播放器、节目列表、播放顺序、下载管理、“我的收听”，以及微信读书 iPad 版的侧栏目录与双栏对开排版，但只将它们映射到本地书籍和 TTS 场景：

- 借鉴（听书）：专注播放页、跨页面常驻迷你播放器、章节队列、播放顺序、断点续听、倍速、定时关闭、后台控制、最近收听、收听统计和缓存管理
- 借鉴（大屏阅读）：常驻左侧目录/笔记侧栏、正文双栏对开、宽屏下的固定行宽与对称页边距、侧栏与正文的选中状态联动、旋转与分屏时不丢阅读位置
- 不照搬：正版内容库、首页推荐、分类运营、精选主题、会员订阅、广告解锁、专辑付费、音频号、主播体系、评论、点评、好友助力、想法圈、读书排行和其他社交能力
- 本地书籍的“章节”对应微信听书的“节目/单集”；书架对应收藏和最近收听入口，但不扩展为在线内容平台
- 缓存管理只适用于已接入的 OpenAI 与微软在线语音合成音频；系统 TTS 没有独立音频文件，不得伪造下载状态或缓存容量
- CarPlay、Android Auto、跨设备同步和在线推荐不属于当前基础功能范围，除非用户后续明确提出

竞品事实以公开商店页面为参考：[微信听书 App Store](https://apps.apple.com/cn/app/%E5%BE%AE%E4%BF%A1%E5%90%AC%E4%B9%A6/id1522424583)、[微信听书 Google Play](https://play.google.com/store/apps/details?hl=zh&id=com.tencent.wehear)。不要复制其受版权、账号或会员体系约束的产品能力，也不要照抄其视觉资产。

## 当前技术栈

- Flutter / Dart，Material 3
- `flutter_riverpod`：全局状态和设置同步
- `go_router`：页面路由
- `shared_preferences`：书籍元数据、阅读设置、TTS 设置和划线的 JSON 持久化
- `file_picker` + `path_provider`：本地文件导入和应用目录管理
- `archive` + `xml` + `html`：EPUB 容器、OPF spine 和 XHTML 文本解析
- `pdfrx`：PDFium 渲染及 PDF 文本提取
- `flutter_tts` + `audio_service` + `audio_session`：系统语音朗读、后台媒体控制、锁屏控制及音频焦点/中断处理
- `just_audio`：云端 TTS 分段 MP3 播放（与 `audio_service` 共用同一播放会话）
- `edge_tts`：Microsoft Edge Read Aloud 兼容 WebSocket 协议，用于无需 API Key 的微软在线神经语音
- `flutter_secure_storage` + `crypto`：API Key 安全存储与云端缓存文件命名
- `google_mlkit_text_recognition`：无文本 PDF 页的端侧中文 OCR（仅 Android/iOS）

不要仅为了匹配旧需求描述而引入 Hive、Bloc、WebView 或 Dio。确有必要新增依赖时，先说明现有方案为何不能满足需求，并控制改动范围。

大屏适配和沉浸式播放一律使用 Flutter 内建能力实现，不得为此新增依赖：

- 断点与自适应：`LayoutBuilder`、`MediaQuery.sizeOf`、`MediaQuery.viewInsetsOf`、`NavigationRail`、`Flexible`/`ConstrainedBox`
- 沉浸式与方向：`SystemChrome.setEnabledSystemUIMode`、`SystemChrome.setPreferredOrientations`、`SystemUiOverlayStyle`
- 不引入 `flutter_adaptive_scaffold`、`responsive_framework`、`sizer` 等布局包；不引入 `screen_brightness`

“朗读时屏幕常亮”没有 Flutter 内建 API，属于**未决项**：要么新增 `wakelock_plus`，要么自写平台通道，要么不做。在用户明确批准之前不要实现，也不要在 UI 中展示该开关。

## 大屏与 iPad 适配规格

目标是「原生 iPad 应用观感」：常驻侧栏目录、正文双栏对开、宽屏下的固定行宽。不是把手机界面等比拉大，也不是简单居中留白。

### 断点定义

采用 Material 3 window size class，以**当前窗口宽度**（`LayoutBuilder` 约束宽，不是物理屏幕宽）判定。iPad 分屏时窗口宽度会实时变化，必须用约束而非 `MediaQuery` 全屏尺寸，否则 Split View 下会误判成大屏。

| 名称 | 窗口宽度 | 导航 | 内容 |
| --- | --- | --- | --- |
| `compact` | < 600dp | 底部 `NavigationBar`（现状） | 单栏 |
| `medium` | 600–839dp | 左侧 `NavigationRail`（收起，仅图标） | 单栏限宽 |
| `expanded` | ≥ 840dp | 左侧 `NavigationRail`（展开，带文字） | 双栏 |

断点判定必须收敛到一处共享工具（例如 `lib/core/breakpoints.dart`），禁止各页面各写一套魔法数字。

### 各页面的大屏形态

**AppShell（`app_router.dart`）**
- `compact`：维持现状——迷你播放器叠在 `NavigationBar` 之上，位于 `bottomNavigationBar`。
- `medium` / `expanded`：导航移到左侧 `NavigationRail`；迷你播放器移到 rail 底部或内容区底部常驻条，**不得因为布局切换而中断播放或重建 `ttsAudioHandler`**。
- 迷你播放器在任何断点下都必须可见且可操作，这是「单一播放事实来源」的一部分。

**书架**
- 网格列数由可用宽度推导（建议按最小卡片宽度约 110–130dp 计算列数），不再硬编码 `crossAxisCount: 3`。
- `expanded` 下列表视图应限制行宽或改为双列，避免出现横贯全屏的单行条目。
- 长按多选、批量操作在 rail 布局下入口位置可变，但行为必须一致。

**重排阅读器（TXT/EPUB）**
- `expanded`：左侧常驻目录/笔记侧栏（可折叠），右侧正文；正文按**双栏对开**排版，两栏共享同一章节内容流，左栏排满后续排右栏。
- `medium`：单栏正文，行宽限制在约 60–75 个汉字（等价约 640–720dp），两侧对称留白；目录仍走抽屉/浮层。
- 双栏对开必须与现有位置模型兼容：位置仍是**章节索引 + 字符偏移**，不得因为分栏而引入第三种定位方式。
- 点击翻页的左右热区按**正文区域**而非窗口宽度划分；侧栏区域的点击不得触发翻页。
- 侧栏目录的选中项必须与正文当前章节联动；朗读跟随翻章时侧栏同步滚动。

**PDF 阅读器**
- `expanded`：左侧常驻缩略图/页码侧栏，右侧 `PdfViewer`。
- PDF 的「双页对开」由 PDFium 的实际页面尺寸决定是否开启；纵横比异常或单页超宽时保持单页，**不得强行拼页**。
- PDF 位置仍是页码 + 归一化矩形，分栏不改变这一点。

**播放器**
- `compact`：维持现有纵向沉浸式布局。
- `medium` / `expanded`：左右分栏——左侧封面、进度、传输控件与倍速；右侧章节队列与朗读文本跟随。横屏下不得出现 `Spacer` 撑破或内容溢出。

**弹层与设置**
- 目录、定时、TTS 设置等 `showModalBottomSheet` 在 `medium`/`expanded` 下改为 `showDialog` 或侧栏内嵌面板，不再使用屏幕高度百分比定高。
- 所有弹层尺寸改为基于内容与约束，`MediaQuery.sizeOf(context).height * .68` 这类写法在大屏必须移除。

### 尺寸变化与状态保持

iPad 旋转、进出 Split View、拖动分隔条都会实时改变窗口尺寸。布局切换时必须满足：

- 播放不中断、不重启、不重复计入收听时长
- 阅读位置（章节 + 字符偏移 / 页码）不丢失、不跳变
- 文本选择、划线弹出菜单可以关闭，但不得崩溃或写入错误位置
- 正在进行的云端 TTS 合成不因 rebuild 被取消或重复发起
- 从 `expanded` 缩到 `compact`（Slide Over）再展开，侧栏折叠状态可重置，但数据状态必须一致

### 明确不做

- 不做 iPad 多窗口（多 Scene）、拖放导入、Apple Pencil 批注、悬停指针态优化
- 不做 macOS / Web / 桌面端适配
- 不为大屏引入独立的路由树或独立页面副本；同一页面用同一份代码按约束渲染

## 沉浸式听书规格

「沉浸式听书」在本项目中特指以下三块能力，全部围绕已有的单一播放源 `ttsAudioHandler` 实现，不新建播放通道。

### 一、全屏沉浸播放页 + 息屏续听

状态（2026-08 核对）：本节除「屏幕常亮」外均已实现；息屏/锁屏场景的真机矩阵验证未完成。

- 播放页进入时通过 `SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)` 隐藏状态栏与导航栏，退出时**必须**恢复 `SystemUiMode.edgeToEdge`；页面异常销毁、返回手势、被系统回收等路径都要还原，不能把系统栏留在隐藏态。【已实现】
- 深色沉浸配色沿用当前播放页；状态栏图标颜色用 `SystemUiOverlayStyle` 显式声明，不依赖主题推断。【已实现】
- 息屏、锁屏、切后台后朗读继续，`audio_service` 的通知与锁屏控件保持标题、章节、播放态、进度同步。【已实现，真机验证未完成】
- 锁屏控件至少提供播放/暂停、上一章/下一章；耳机线控与蓝牙媒体键映射到同一组意图。【已实现，真机验证未完成】
- 屏幕常亮是未决项（见「当前技术栈」），在批准前不实现、不展示开关。【未实现，保持未决】

### 二、阅读页边读边听（朗读跟随）

状态（2026-08 核对）：本节除「双栏对开跨栏跟随」外均已实现。

- 高亮粒度以**句**为单位对齐，避免系统 TTS 回调抖动导致的逐字闪烁；无回调时降级为整段高亮或不高亮，不得伪造进度。【已实现：`lib/core/sentence_bounds.dart` + `test/sentence_bounds_test.dart`；无回调/空区间时不高亮】
- 自动滚动只在「正在播放且当前章节 == 朗读章节」时生效；用户手动滚动后应暂停自动跟随一小段时间，避免与用户操作抢夺滚动位置。【已实现：手动滚动/点按翻页/跳章后让位约 4 秒，之后随下一次进度回调恢复】
- 读→听、听→读切换时定位一致，共用同一份「章节索引 + 字符偏移」，禁止为跟随另建一套位置。【已实现：正文选中「朗读」与侧栏划线「从此处朗读」同样走这份位置】
- 大屏双栏对开下，跟随高亮必须能跨栏推进，并在跨栏/跨章时正确滚动侧栏目录选中项。【未实现：双栏对开本身未实现；侧栏选中态已联动，但列表不自动滚动】
- PDF 走按页跟随：自动翻到朗读页并浮层展示当前文本片段，**不伪造 PDF 坐标高亮**。【已实现】

### 三、打断与恢复的完整策略

状态（2026-08 核对）：`tts_audio_handler.dart` 已通过 `audio_session` 统一处理音频焦点与中断事件，对 builtin 与云端两条引擎路径做同样的暂停/恢复决策；中断暂停不计入有效收听。**尚未完成**：来电、耳机、蓝牙场景的真机验证，杀进程恢复路径的系统验证，以及云端网络失败时自动回退系统朗读。期望行为对照：

| 事件 | 期望行为 | 状态 |
| --- | --- | --- |
| 来电、闹钟、其他 App 抢占焦点 | 暂停并记录位置；短暂中断结束后可恢复，长期丢失焦点则保持暂停 | 已实现，真机未验证 |
| 临时降低音量（ducking） | Android 可降音继续或暂停，取一种并保持一致；不得静音空转 | 已实现（降音继续），真机未验证 |
| 耳机拔出 / 蓝牙断开 | 立即暂停，不得转外放继续朗读 | 已实现，真机未验证 |
| 蓝牙路由切换 | 保持播放，位置不跳变 | 未验证 |
| 进程被杀后重启 | 恢复到同一本书、同一章节和合理误差内的字符位置 | 部分：`AudioProgress` 已持久化，完整路径未系统验证 |
| 云端 TTS 网络失败 | 明确提示并可回退系统朗读，不静默停在「正在播放」 | 部分：有明确提示，自动回退未实现 |

统一要求：

- 所有中断路径都必须写回 `AudioProgress`，且遵守时间戳合并规则——延迟到达的旧回调不得覆盖较新位置。
- 中断导致的暂停不得计入 `ListeningRecord` 的有效收听秒数。
- 恢复策略必须可预测且在真机验证；模拟器无法覆盖来电、蓝牙与耳机，验证结论要注明设备。
- 保留 `_operation` 单调 token 模式：任何重启朗读的异步路径在每次 await 后重新校验 token，防止中断恢复时旧分段复活。

### 沉浸式听书明确不做

- 不做播放页手势操作（双击暂停、滑动切章、上下滑调速）
- 不做 CarPlay / Android Auto
- 不做音效、均衡器、音量归一化

## 必须尊重的技术事实

### 大屏适配不得破坏既有约束

自适应布局是**渲染层**改动，不是架构改动。禁止以「大屏需要」为由：

- 新建页面级播放状态或第二条播放路径
- 为分栏改动 `ReadingLocation` 的两种定位语义
- 给 PDF 套用重排设置，或给重排阅读器引入页码定位
- 复制页面代码为 `xxx_tablet.dart`


### EPUB 是简化重排，不是浏览器级还原

当前 EPUB 方案把 XHTML 转为纯文本后由 Flutter 重排。它有利于统一主题、选择、划线和 TTS，但不会完整保留复杂 CSS、表格、浮动布局、脚注、图片和多媒体。不要宣称已经实现所见即所得 EPUB，也不要在没有迁移方案和回归验证的情况下改成 WebView。

### PDF 与重排阅读器必须保持分离

PDF 是固定版式，不能套用 TXT/EPUB 的字号、行距或字符偏移定位。PDF 标注应使用页码和归一化坐标；如果实现 PDF 文本选择或标注，必须单独设计交互和定位，不得伪造重排能力。

PDF 文本提取和 OCR 都只能尽力而为。分栏、页眉页脚、字符映射、倾斜页面和扫描清晰度会降低质量；不能因为文件能显示或 OCR 返回了文字就声称能可靠听书。

### TTS 回调不保证跨平台精确

`flutter_tts` 的 progress、pause、voice 和字符范围行为会随 Android/iOS、系统版本及语音引擎变化。高亮同步必须有无回调时的降级方案，不能承诺逐词或逐句 100% 精准。

### OpenAI 与微软免密在线语音已接入

OpenAI 当前通过 `/v1/audio/speech` 生成分段 MP3，并由统一播放器播放和缓存。连接校验会发起真实鉴权请求，API Key 保存到系统安全存储。`TtsProvider.azure` 当前承载的是无需 Key 的 Microsoft Edge Read Aloud 兼容接口，不是正式 Azure Speech API；界面和文档必须持续明确这一边界。阿里云仍不得描述为可用。后续修改必须继续满足：

- 为每个提供商实现独立适配器，而不是在页面里直接发 HTTP 请求
- 使用安全存储保存 API Key，禁止以明文 SharedPreferences 或日志保存生产密钥
- 保持分段合成、缓存、取消和错误提示；继续补齐自动重试、限流说明、费用风险和离线回退
- 将合成音频接入 `audio_service` 播放链路，并保持章节/字符进度语义一致
- 使用服务商官方文档和可替换配置，不硬编码密钥、地区或模型

### 播放状态必须只有一个事实来源

完整播放器、全局迷你播放器、阅读器听书入口、个人中心最近收听和系统媒体控件必须共享同一个播放会话与状态流。页面只能订阅和发送意图，不能各自维护 `playing`、当前章节、字符偏移、语速或队列副本。

后续实现至少需要补齐以下持久化接口，并对已有 JSON 数据保持向后兼容：

- `AudioProgress`：`bookId`、`chapterIndex`、`characterOffset`、`speed`、`updatedAt`
- `PlaybackMode`：`sequential`、`reverse`、`repeatOne`
- `PlaybackQueueState`：当前书籍、章节队列、当前索引和播放模式
- `ListeningRecord`：书籍、章节、开始/结束时间、有效收听秒数和最后字符位置

新增字段必须有默认值；未知枚举、损坏记录和已删除书籍应被安全忽略或迁移，不能导致应用初始化失败。

### 仿真翻页不是当前优先级

现有阅读器采用 `PageView` 章节滑动。覆盖翻页、分页排版和 3D 仿真翻页尚未实现。除非任务明确要求，否则优先修复数据正确性、进度同步、导入兼容性和后台播放，不要先投入高风险动画。

## 听书关键验收场景

- 播放到章节中段后杀死进程并重启，能恢复到同一本书、同一章节和合理误差内的字符位置
- 播放期间在书架、搜索、个人中心、完整播放器之间切换，声音不中断，迷你播放器和系统媒体控件状态一致
- 顺序、倒序、单章循环在章节结束时执行正确；首尾章节不会越界或形成意外死循环
- 进度拖动、15 秒快退/快进后，高亮、后台媒体信息和持久化位置同步更新
- 从阅读切到听书、再切回阅读时定位一致；延迟到达的旧 TTS 回调不会把进度回退
- 来电、闹钟、其他音频抢占、耳机拔出和蓝牙切换时按平台规范暂停或降级，恢复策略可预测
- 空章节、空书、损坏文本和扫描 PDF 不崩溃；无法听书时给出明确原因且不创建无效播放记录
- 删除书籍后同步清理或隐藏其播放队列、进度、历史和云端音频缓存，不影响其他书籍
- 清理单条历史、全部历史或统计数据后，列表、累计时长和存储状态立即一致
- 系统 TTS 模式不显示虚假的音频下载；云端 TTS 缓存失败时仍可提示并回退到系统朗读

## 大屏与沉浸式关键验收场景

- iPad 横屏打开一本 EPUB，左侧目录常驻、正文双栏对开；点选目录跳章后两栏内容连续，字符偏移记录正确
- 在双栏对开状态下开始听书，高亮从左栏推进到右栏再跨到下一章，侧栏选中项同步；切回竖屏后位置一致
- 播放中把 App 从全屏拖到 Split View 1/2 再拖到 1/3，声音不中断、不重复计时，迷你播放器在 rail 和底栏两种形态间切换后仍可操作
- iPhone 横屏打开播放器，左右分栏无溢出、无 `Spacer` 撑破；返回后系统状态栏恢复正常显示
- 进入沉浸播放页后用手势返回、或被系统回收，再回到书架时状态栏与导航栏均已恢复
- 息屏后朗读继续，锁屏控件显示正确书名与章节；按锁屏「下一章」后解锁，App 内章节与之相同
- 播放中来电（真机）：自动暂停并记录位置；通话结束后按既定策略处理，中断时段不计入收听时长
- 播放中拔出耳机：立即暂停且不转外放；重新插入或连接蓝牙后可从原位置继续
- 云端 TTS 合成过程中旋转设备或进出分屏：合成不被取消、不重复发起，完成后正常播放
- 大屏书架在不同宽度下列数自适应，长按多选与批量删除行为与手机一致
- 弹层（目录、定时、TTS 设置）在大屏以对话框或内嵌面板呈现，内容不被裁切、不出现大片空白

## 开发规则

1. 先检查 `git status`、仓库说明、相关代码和现有测试，保留用户已有改动，不覆盖无关文件。
2. 以 `docs/erdu-mockup.html` 为交互和视觉基准，但数据、错误、空状态和平台差异必须按真实 App 处理。原型只描述手机形态，大屏形态按「大屏与 iPad 适配规格」推导，不要因为原型没画就省略。
3. 优先增量复用 `AppController`、`BookRepository`、现有模型和路由，不在页面中复制持久化或业务逻辑。
4. 所有异步 UI 操作检查 `mounted`；所有索引、页码、字符偏移和空章节处理边界值。
5. 布局判定一律基于 `LayoutBuilder` 约束宽度，不用物理屏幕尺寸或平台判断（`Platform.isIOS` 不等于手机，iPad 也是 iOS）。断点常量集中定义，不散落魔法数字。
6. 文件导入失败要给用户可理解的提示，并清理失败流程产生的孤立副本。
7. 数据模型变更必须兼容旧 JSON；不得让已有用户数据因字段新增或枚举变化而无法加载。
8. API Key 不得出现在源码、日志、测试快照或提交内容中。涉及生产密钥时使用平台安全存储。
9. 不使用“已支持”“已连接”“精准同步”等措辞描述尚未真实贯通或只能尽力而为的功能；“已适配 iPad”必须以真机或模拟器上的横屏与分屏验证为前提。
10. 修改后运行格式化、静态分析和相关测试；影响原生能力时至少尝试对应平台构建。
11. 不用占位代码、伪实现或“其余逻辑类似”。若受平台、网络或服务商限制无法完成，明确说明阻塞点和可验证的降级行为。

## 工作与交付方式

- 直接在现有仓库完成用户指定任务，不要求用户逐步回复“继续”。
- 开始时用简短说明列出将检查的模块和关键假设。
- 实现过程中保持改动聚焦；如果发现相邻问题会影响当前功能，可一并修复并说明原因。
- 最终交付必须包含：完成内容、关键文件、真实限制、执行过的验证及其结果。
- 如果测试或构建因环境失败，要区分代码失败与工具链/网络失败，附上最关键的错误信息，不得把未运行的验证写成通过。

涉及布局改动时，额外在以下形态上人工验证并记录结果；无法覆盖的形态要写明「未验证」而不是省略：

- iPad Split View 1/2 与 1/3、Slide Over

## 完成定义

只有同时满足以下条件，任务才算完成：

- 用户指定的交互能够从 UI 到状态、持久化或平台服务完整走通
- 重启、空数据、损坏输入和取消操作有合理行为
- 没有破坏 TXT/EPUB/PDF 三条独立阅读路径
- 没有破坏阅读设置与全局主题同步
- 涉及布局的改动在 compact / medium / expanded 三种宽度下均无溢出、无裁切、无重复播放状态
- 涉及沉浸模式的改动在退出、返回和异常销毁路径上都恢复了系统栏
- 相关测试已新增或更新，静态分析无问题
- 文档描述与真实实现一致，未把 UI 原型或配置表单当成后端能力；未把「iPad 能安装」写成「已适配 iPad」
